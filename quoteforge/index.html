The QuoteForge lane

One continuous fictional workflow.

Follow the gold thread from intake to receipt. Gold marks decisions and evidence. Lychee red marks a stop. This is not a multi-trade product tour.

  1. 01
    Messy enquiry enters

    The original fictional request stays visible. Nothing is inferred yet.

  2. 02
    Admitted facts and unknowns

    Named fields surface. Missing information stays missing — never invented.

  3. 03
    Approved rules are checked

    Owner exclusions and authority limits decide what may proceed before any price is spoken.

  4. 04
    Deterministic NZD calculation

    Arithmetic runs only against the admitted pricebook. No quote total is invented.

  5. 05
    Review, ask, or stop

    The same governed workflow either prepares a review draft, names missing facts, or stops.

  6. 06
    A person decides

    Edit, approve for review, reject or hold. Authority stays with the business.

  7. 07
    Correction preserves the old result

    The owner-corrected quantity becomes a new revision. The original run remains inspectable.

  8. 08
    Exact replay reconciles

    The corrected run replays to the same receipt. A digest is tamper evidence, not a signature.

What it refuses

Stops are product behaviour.

  • Inventing a rate or filling a missing required fact.
  • Sending, booking, charging, invoicing or publishing anything.
  • Treating a review-ready draft as an approved customer quote.
  • Connecting Xero, Tradify, Fergus, email or payments at activation.

A real pilot still needs

Evidence, not a score.

  • Owner-supplied price lists, exclusions and templates.
  • A written permission boundary before any live workflow.
  • Human review of every customer-facing draft.
  • Measured baseline evidence — not a readiness score or time-saved claim.

Where evenings disappear

The quoting bottleneck, not a chatbot catalogue.

QuoteForge is shaped around owner-led NZ trade and service quoting. Later abilities wait until this lane is understood.

01

Incomplete enquiries

A customer writes that they need a quote. Product, address and site facts are missing. Evenings disappear in back-and-forth before a scope exists.

02

Rebuilding the same draft

Owners retype line items from memory or last month's spreadsheet instead of starting from a structured, reviewable handoff.

03

Unapproved rates

Quoting from memory or a stale pricebook is how margins leak. Arithmetic should only run against an owner-admitted rate card.

04

Work that should have waited

Site visits and calendar locks happen before product, access and budget are known. A safe stop is cheaper than an unqualified drive.

Authority split

Model interprets. Code enforces. You decide.

Language models help structure language. Deterministic software owns the arithmetic. Humans own commitments. That split is the product.

Model

AI

Extract facts, classify the job, and draft follow-up language inside approved sources.

Does not: Invent rates, lock bookings, or send to the customer.

Code

CODE

Look up admitted rates, enforce no-price / no-booking rules, and withhold incomplete totals.

Does not: Override an owner boundary or invent a missing required fact.

Owner

YOU

Approve, edit, hold or stop. Send the message. Own the quote.

Does not: Delegated to the specialist.

Why generic chat fails here
