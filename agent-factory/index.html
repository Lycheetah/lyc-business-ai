The build loop

Every stage leaves something reviewable behind.

A plausible answer is not business truth. Each hand-off makes the source, authority, uncertainty and next decision easier to inspect. This is the manufacturing sequence after the first useful outcome is understood.

  1. 01
    Bound one workflow

    Name one painful, repeatable outcome, one accountable owner and the decisions that must remain human. Capture a baseline before promising automation.

    Workflow boundary + baseline

  2. 02
    Preserve business truth

    Collect the minimum approved sources, rules, examples and exclusions. Conflicts and unknowns stay visible instead of being silently resolved.

    Source manifest + operating pack

  3. 03
    Draft the specialist

    Map the workflow to a specialist blueprint: model work, deterministic work, human authority, required fields, permissions and safe-stop conditions.

    Blueprint + owner field map

  4. 04
    Test synthetic work

    Run normal, missing-information, adversarial, safe-stop and regression cases against the fixed configuration before any real business record is admitted.

    Evaluation scorecard + corrections

  5. 05
    Pilot with control intact

    Use draft-first outputs with human review, receipts and a measured day-30 decision. Continue, expand or stop remains the owner’s choice.

    Pilot evidence + continuation decision

What the owner can inspect

Drafts and evidence before access.

The local setup flow is deliberately review-first. It can carry a business from discovery to a field-mapped configuration draft without uploading raw documents, calling a provider or activating an agent.

01

Discovery draft

Requires owner review

The workflow, owner, source manifest, storage boundary and controls are recorded without admitting raw file contents.

02

Specialist blueprint

Requires owner review

The authority split, source-alignment gaps, required fields and synthetic-evaluation gate are made explicit.

03

Configuration draft

Ready for synthetic evaluation

Every required field is mapped to a human label, description and admitted source reference. Activation is still disabled.

Permission by design

Useful work without quiet authority creep.

The specialist is allowed to be helpful inside a written boundary. It is not allowed to turn uncertainty into a commitment. This is the intended operating split, not a certification.

Inside the boundary

  • Retrieve approved knowledge inside the agreed workflow
  • Structure incoming information and identify what is missing
  • Apply deterministic calculations owned by code
  • Prepare drafts, handoffs and next-action suggestions
  • Show sources, uncertainty, permissions and receipts

A human still owns

  • Invent a price, rule or source when the business is silent
  • Approve a canonical rule or widen its own permissions
  • Send messages, book work, invoice, charge or publish
  • Make a binding customer commitment
  • Turn a synthetic witness into a production claim

Deeper · decision layer

Name the bottleneck before buying the tool.

GrowthForge is one business-facing agent inside the wider LYC system. It takes an owner's stated goal, workload evidence, constraints and candidate interventions, then compares conservative, expected and optimistic ranges so the next move can be inspected against the owner's own limits.

Hard boundary

GrowthForge does not install the chosen tool, approve a budget, change a business rule or promise growth. The factory builds a separate customer specialist only after the owner approves the next boundary.

01

Bottleneck

Name the stage where time, capacity, cost or risk is constraining the work.

02

Viability range

Show returned capacity, net value, review load and payback against the owner's limits.

03

Decision gate

Return viable, more information, not viable, human review or safe stop—with evidence and unknowns visible.
